Guía de lecturaClima INIFAP

1. Qué hace el proyecto

Clima INIFAP es una aplicación para consultar información del clima registrada por estaciones ubicadas en Zacatecas. La persona puede escoger una estación, ver sus datos actuales, revisar información de días anteriores, consultar reportes, verla en un mapa y guardar hasta tres estaciones favoritas. La aplicación también conserva la información más reciente para seguir mostrando algo útil cuando no hay internet.

La aplicación

Está hecha con Flutter y Dart. La pantalla principal está en WeatherProxyPage.dart. Las demás funciones se reparten en archivos para el mapa, favoritos, reportes, datos anteriores y alertas.

De dónde salen los datos

La aplicación pregunta al servidor de INIFAP por medio de apiApp2.php. En cada petición envía un número que indica qué información necesita y, cuando corresponde, el ID de la estación.

Qué pasa si el servidor bloquea la app

Existe una copia de respaldo en GitHub. Si el servidor responde con el error 403, la aplicación intenta leer esa copia. También conserva datos dentro del teléfono.

Cómo se actualiza el respaldo

GitHub ejecuta un navegador automático cada 15 minutos. Ese navegador consulta la información y vuelve a crear el archivo data/latest.json.

2. Cómo funciona por dentro

La idea general es sencilla: la pantalla pide información, un servicio intenta obtenerla del servidor y después la guarda para usarla más tarde. Si el servidor no permite la consulta, el servicio busca la misma información en la copia de GitHub.

Plan alternativoSe usa cuando aparece 403

Secuencia de arranque

  1. main() abre la aplicación y muestra la pantalla principal lo antes posible.
  2. Después prepara las notificaciones y la tarea que revisa el clima aun cuando la aplicación está cerrada.
  3. WeatherProxyPage._boot() carga la lista de estaciones. Primero usa la lista guardada y después busca una más reciente.
  4. Recupera la última estación que usó la persona y muestra los últimos datos guardados.
  5. OfflineDataService.syncFromNetwork() intenta descargar información nueva y actualizar la copia que está dentro del teléfono.

Decisión de red

Petición de pantalla
  └─ OfflineDataService.sharedClient
       ├─ API responde distinto de 403 → usar respuesta directa
       ├─ API responde 403 → buscar sección equivalente en el espejo
       ├─ API falla → intentar espejo
       └─ espejo no cubre la consulta → devolver el error original

Pantalla
  ├─ si recibió datos → leerlos, mostrarlos y guardarlos
  └─ si falló → conservar los últimos datos y mostrar un aviso
Importante: todas las consultas nuevas deben usar OfflineDataService.sharedClient. Ese es el servicio que sabe cambiar automáticamente a la copia de GitHub. Si se usa una conexión diferente, la nueva pantalla puede dejar de funcionar cuando aparezca el error 403.

Por qué existen dos listas de estaciones

StationService empieza con la lista incluida en la aplicación, llamada kStations. También revisa si el teléfono ya tiene una lista guardada y finalmente pregunta al servidor por una lista nueva usando r=all. Si el servidor responde correctamente, esa lista más reciente se usa durante la sesión. Aun así, la lista incluida en el código sigue siendo necesaria: permite abrir la aplicación por primera vez aunque el servidor esté caído o no haya internet.

4. Qué información pide al servidor

Todas las consultas se envían a https://zacatecas.inifap.gob.mx/apiApp2.php. En la dirección se agrega el valor r. Ese valor funciona como una opción de menú: le dice al servidor si queremos la lista de estaciones, la información actual, la lluvia, el viento o los datos de todo un mes.

rFunción en la appParámetrosEspejo

1Reporte: tiempo real.Ninguno.reports.r1
3Reporte: resumen TR.Ninguno.reports.r3
4Reporte: avance mensual.Ninguno.reports.r4
5Tiempo real por estación.día, mes, año, ID.realtime.<id>
6Precipitación diaria.día, mes, año, ID.daily.<id>.r6
7Humedad diaria.día, mes, año, ID.daily.<id>.r7
8Radiación diaria.día, mes, año, ID.daily.<id>.r8

10Histórico mensual.mes, año, ID.history.<id>

Ejemplos exactos

// Tiempo real de Calera, CEZAC
...?r=5&day=29&month=09&year=2026&id_est_given=18851

// Histórico del mes
...?r=10&month=09&year=2026&id_est_given=18851

// Reporte general
...?r=4

Campos de catálogo esperados

Station(
  int.tryParse(json['IdEstacion']?.toString() ?? '0') ?? 0,
  json['NombreEstacion']?.toString() ?? 'Desconocida',
);
El servidor no siempre entrega los datos con la misma forma. Por eso el código reconoce varios nombres posibles para un mismo dato. Antes de agregar una consulta nueva o cambiar un nombre, guarda una respuesta real y revisa si contiene una lista o un solo elemento, si los datos vienen dentro de otra sección, si los decimales usan coma y si hay valores vacíos.

Limitación temporal del espejo

La copia de GitHub sólo contiene el día y el mes de su actualización más reciente. Si alguien pide información de otro día o de otro mes, esa copia puede devolver la información más nueva en lugar de la fecha solicitada. Los datos guardados dentro del teléfono ayudan únicamente si esa fecha ya se consultó antes.

5. Agregar una estación

Antes de editar: consigue el ID oficial, nombre oficial y coordenadas. Prueba el ID contra la API. No reutilices el ID de una estación “parecida”.
1

Validar el origen

Consulta r=5 con la fecha actual y r=10 con el mes actual. Después comprueba r=6..9. Una respuesta HTTP 200 no basta: debe contener registros de esa estación.

https://zacatecas.inifap.gob.mx/apiApp2.php
  ?r=5
  &day=29
  &month=09
  &year=2026
  &id_est_given=12345
2

Agregarla a la lista incluida en la aplicación

Edita lib/data/Stations.dart. Esta lista permite que la estación siga apareciendo aunque no haya internet. Mantén el orden existente y guarda el archivo con codificación UTF-8 para que los acentos se vean correctamente.

const List<Station> kStations = [
  // ...
  Station(12345, 'Municipio, Nombre de la estación'),
];
3

Registrar coordenadas

Edita lib/data/lat_and_long_cords.dart. Usa grados decimales: Zacatecas normalmente tiene longitud negativa.

const Map<int, LatLng> kStationCoords = {
  // ...
  12345: LatLng(22.770000, -102.570000),
};
Por qué son dos archivos: el catálogo define qué se puede seleccionar; las coordenadas definen qué puede dibujarse. En maps.dart, un ID sin coordenadas se descarta al construir marcadores.

5. Agregar una estación — copia de respaldo

4

Agregar el ID al programa que crea el respaldo

Edita scripts/scrape.js. Este programa abre el servidor como si fuera un navegador y guarda una copia de los datos. No lee automáticamente la lista de Dart, por lo que el ID debe agregarse aquí también.

const STATION_IDS = [
  18851, 26684, /* ... */,
  12345,
];

Al incluirlo, la siguiente corrida intentará:

  • realtime["12345"] mediante r=5.
  • daily["12345"].r6..r9.
  • history["12345"] mediante r=10.
5

Volver a crear la copia de respaldo

Hay dos maneras. La primera es abrir la sección Actions de GitHub y ejecutar manualmente “Scrape INIFAP”. La segunda es hacerlo desde la computadora con estos comandos:

cd scripts
npm install
node scrape.js

La salida correcta termina con un mensaje parecido a:

✅ Guardado .../data/latest.json (38/38 estaciones completas).
No edites data/latest.json a mano. Es un artefacto generado. El cron lo reemplazará y tu estación volverá a faltar si no está en STATION_IDS.
6

Verificar claves generadas

realtime.12345
daily.12345.r6
daily.12345.r7
daily.12345.r8
daily.12345.r9
history.12345

El archivo puede crearse aunque falte una parte de la estación. Esto ocurre porque el programa muestra una advertencia y continúa cuando una consulta individual falla. Por eso hay que comprobar todas las claves anteriores y no limitarse a revisar que el archivo exista.

7

Publicar en la rama correcta

La aplicación busca el archivo en JoelSANQ/inifap/notifications/data/latest.json. La palabra notifications es la rama de Git. Si el archivo se publica en otra rama o el repositorio cambia de dueño, modifica también _kMirrorUrl dentro de generate_offline.dart.

6. Cómo funciona sin internet

La aplicación guarda una copia de la información que logró descargar. Así puede abrirse y mostrar los datos más recientes aunque la conexión se pierda. Hay dos formas de guardado: datos pequeños, como el ID de la última estación, y un archivo más grande con clima, históricos y reportes.

Archivo grande guardado en el teléfono o computadora

Se guarda como offline_data.json en el directorio de documentos de la aplicación, obtenido con getApplicationDocumentsDirectory().

{
  "generated_at": "2026-09-29T...",
  "reports": { "r1": [], "r3": [], "r4": [] },
  "history": { "18851": { "2026-09": [] } },
  "daily_extras": {
    "18851": { "2026-09-29": { "r6": [], "r7": [], "r8": [], "r9": [] } }
  },
  "realtime": { "18851": [] }
}

Por qué los dos archivos no se ven iguales

El archivo del teléfono organiza los históricos por año y mes, y la información diaria por año, mes y día. La copia de GitHub tiene una organización más corta. El código llamado _WafFallbackClient toma la parte necesaria de la copia de GitHub y la entrega a la pantalla como si hubiera venido directamente del servidor.

No cambies la forma de estos archivos sin revisar todo el recorrido. Si cambia la copia de GitHub, también debe cambiar _lookupInMirror. Si cambia el archivo del teléfono, deben actualizarse las funciones que guardan datos, cuyos nombres comienzan con save, y las funciones que los leen.

7. Copia de respaldo en GitHub

GitHub puede ejecutar tareas automáticas aunque ninguna persona tenga abierta la aplicación. En este proyecto, la tarea se llama “Scrape INIFAP” y su definición está en .github/workflows/scrape-inifap.yml.

Qué hace la tarea automática

  1. Se ejecuta aproximadamente cada 15 minutos o cuando una persona la inicia manualmente.
  2. Descarga una copia del repositorio.
  3. Prepara Node 24, que es el programa necesario para ejecutar el archivo JavaScript.
  4. Instala Puppeteer, que controla un navegador de manera automática.
  5. Ejecuta node scrape.js para consultar las estaciones.
  6. Si data/latest.json cambió, guarda la nueva versión en GitHub.
permissions:
  contents: write

on:
  schedule:
    - cron: '*/15 * * * *'
  workflow_dispatch: {}

Qué debe estar configurado para que funcione

RevisiónPor qué
Actions → General → Workflow permissionsDebe permitir escritura del bot.
Protección de ramaPuede bloquear el push automático.
Rama de ejecuciónDebe coincidir con la rama codificada en _kMirrorUrl.
Mensajes de ejecuciónEl proceso continúa aunque falle una consulta individual; hay que leer las advertencias.
fetched_atIndica frescura de la instantánea.
Tamaño del JSONUn cambio brusco puede revelar una respuesta vacía o formato nuevo.

Qué hacer si falla

  1. Abre la ejecución fallida en GitHub y busca la primera respuesta que no sea 200.
  2. Prueba si la página de INIFAP abre normalmente en un navegador.
  3. Vuelve a ejecutar la tarea para descartar un corte momentáneo.
  4. Si sólo falla una estación, prueba por separado cada tipo de información de esa estación.
  5. No escribas datos inventados dentro de latest.json. Es mejor conservar la última copia correcta mientras se investiga.
La lista general r=all puede fallar sin detener todo. En ese caso la tarea continúa porque la aplicación tiene su propia lista llamada kStations. En cambio, una falla en los reportes generales puede detener la ejecución completa.

Cuándo se podría quitar esta copia de respaldo

Sólo debe retirarse cuando INIFAP confirme que el servidor ya permite consultas desde teléfonos de manera estable. Primero hay que probar todos los tipos de información durante varios días. Después se puede quitar la copia de manera gradual, conservando los datos guardados en el teléfono. Una sola prueba correcta no es suficiente.

Selección de estación

itemCount: StationService.instance.stations.length
...
final st = StationService.instance.stations[i];
...
await _fetch();

El selector usa la lista que StationService tiene preparada en ese momento. Normalmente será la lista más reciente obtenida del servidor. Si el servidor no entregó ninguna, se usa kStations, que es la lista incluida dentro de la aplicación.

Mapa

final LatLng? ll = kStationCoords[st.id];
if (ll == null) continue;

La ausencia de coordenadas no impide otras consultas, pero sí elimina el marcador. Un ID duplicado apunta a una única coordenada y puede presentar un nombre incorrecto en el mapa.

Favoritos

Los IDs favoritos se guardan como texto bajo el nombre favorite_station_ids. Cuando alguien agrega o elimina una estación, favoritesVersion avisa al mapa y a la barra de favoritos para que ambos se actualicen. La pantalla permite guardar como máximo tres estaciones.

Conectividad

Las pantallas esperan tres segundos antes de mostrar el aviso de “sin conexión”. Esto evita que el mensaje aparezca por un cambio muy breve de señal. Cuando regresa internet, la pantalla intenta descargar nuevamente la información que estaba mostrando.

Versión web: el código intenta pasar las consultas por http://localhost:8080, es decir, por un programa auxiliar que debería estar ejecutándose en la misma computadora. Ese programa no está incluido en el repositorio. Por eso la versión web necesita que se agregue ese servicio o que se cambie la forma de conectarse.

9. Cómo funcionan las alertas

Android puede despertar la aplicación de vez en cuando para revisar el clima de las estaciones favoritas, incluso si la pantalla está cerrada. La herramienta que organiza esa revisión se llama WorkManager. Cuando encuentra una condición importante, la aplicación muestra una notificación local en el teléfono.

Límites que producen una alerta

AlertaCuándo apareceNombre usado para recordar el último aviso
Heladatemp < 0extreme_temp_notif_<id>
Calortemp > 38misma clave de temperatura
Vientowind > 23 km/hhigh_wind_notif_<id>
Lluviarain >= 1.0 mmrain_notif_<id>
 
const cooldown = 15 * 60 * 1000;

if (temp != 999.0 && (temp < 0 || temp > 38)) { ... }
if (wind > 23) { ... }
if (rain >= 1.0) { ... }

La revisión se solicita cada 15 minutos, pero Android puede retrasarla para ahorrar batería. La aplicación recuerda la hora del último aviso y espera otros 15 minutos antes de repetir el mismo tipo de alerta para la misma estación. Cuando no hay internet se usa la información guardada. Esa información no incluye viento, por lo que la alerta de viento no puede calcularse sin conexión.

Los comentarios del código no coinciden: algunos dicen que la espera es de cinco minutos, pero la operación matemática real usa 15 minutos. El comportamiento verdadero es el del código.

Permisos que necesita Android

El archivo AndroidManifest.xml solicita permiso para usar internet, mostrar notificaciones, mantener una tarea activa durante unos momentos y volver a programarla después de reiniciar el teléfono. Si en el futuro se actualiza la versión objetivo de Android, estos permisos deben revisarse porque las reglas de Android cambian con el tiempo.

El archivo pubspec.yaml indica que el proyecto necesita Dart ^3.6.1. Dart viene incluido con Flutter, por lo que hay que instalar una versión de Flutter compatible. El primer comando revisa si faltan herramientas; el segundo descarga los paquetes del proyecto; el tercero muestra teléfonos y emuladores disponibles; el cuarto abre la aplicación.

Android

# Debug en dispositivo/emulador
flutter run -d <device-id>

# APK universal de entrega
flutter build apk --release

# Opcional: APK por arquitectura
flutter build apk --split-per-abi

El archivo instalable queda normalmente en build/app/outputs/flutter-apk/. Antes de publicarlo, hay que revisar el nombre visible de la aplicación, su identificador único, la firma digital y el número de versión. Actualmente aparecen com.example.clima y clima, que todavía parecen nombres de desarrollo.

Programa que actualiza la copia de GitHub

cd scripts
npm install
node scrape.js

Este proceso necesita internet y un navegador Chromium. Consulta una estación después de otra, por lo que puede tardar varios minutos. Hay que dejarlo terminar y leer el resumen final para saber cuántas estaciones se copiaron correctamente.

Web

Ejecutar flutter run -d chrome no es suficiente, porque el proyecto espera el programa auxiliar del puerto 8080. Si la versión web se va a entregar, primero debe resolverse esa pieza faltante.

Para saber exactamente qué versión se entregó: anota la versión de Flutter, el identificador del cambio en Git, la fecha y el nombre del APK. Si es posible, guarda también la huella SHA-256 del archivo.

11. Cómo comprobar los cambios

Comandos que deben ejecutarse

dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
Estado actual de pruebas: test/widget_test.dart conserva la prueba de contador de la plantilla Flutter. Busca textos “0/1” y un icono “+” que no representan la app. Debe sustituirse; un fallo ahí no demuestra una regresión climática, pero tampoco debe ignorarse indefinidamente.

Cuándo se puede decir que una estación quedó bien

  1. Su ID aparece una sola vez en la lista y en las coordenadas.
  2. El mismo ID aparece una sola vez en scripts/scrape.js.
  3. El nombre y los acentos se leen correctamente.
  4. El marcador aparece en el lugar correcto del mapa.
  5. Los datos actuales y los históricos realmente pertenecen a esa estación.
  6. Después de cargarla con internet, sigue mostrando datos en modo avión.
  7. La copia de GitHub funciona cuando el servidor responde 403.
  8. Las estaciones que ya existían siguen funcionando.

Orden recomendado para buscar el problema

  1. Confirmar que el ID es el oficial y que el servidor entrega datos para él.
  2. Confirmar qué lista de estaciones está usando el teléfono.
  3. Confirmar que existe una coordenada con el mismo ID.
  4. Buscar el ID dentro de latest.json.
  5. Comprobar que la dirección de GitHub apunta al repositorio y rama correctos.
  6. Probar primero con internet y después en modo avión.
  7. Leer los mensajes de Flutter, Android y GitHub Actions.

Cómo recuperar el sistema sin perder información útil

Antes de borrar los datos del teléfono, toma capturas y anota los pasos que producen el problema. No borres data/latest.json si el servidor de INIFAP está caído, porque una copia vieja sigue siendo mejor que no tener información. Si GitHub publicó un archivo incorrecto, recupera la última versión buena con Git y después corrige scripts/scrape.js, que es el archivo que lo genera.

Mejora recomendada: fuente única de estaciones

Lo más seguro sería guardar ID, nombre y coordenadas juntos en una sola lista. A partir de esa lista se podría crear automáticamente la lista que usa scripts/scrape.js. Mientras eso no exista, una prueba automática debería impedir que se suban cambios cuando falte un ID o haya uno repetido.

class Station {

}

Seguridad y datos

  • No guardes contraseñas, cuentas administrativas ni archivos privados dentro del repositorio.
  • android:usesCleartextTraffic="true" permite conexiones sin cifrado. Debe revisarse antes de publicar una versión definitiva.
  • No publiques información privada obtenida de un teléfono durante las pruebas.
  • Si se cambia el proveedor del mapa, revisa sus condiciones de uso y la forma correcta de darle crédito.
